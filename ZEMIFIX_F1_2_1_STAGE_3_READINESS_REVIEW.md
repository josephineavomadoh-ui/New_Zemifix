## 1. Authentication Bootstrap Security Design

When Migration `20261119000002_stage2_1_default_deny_rls` is applied, `stage2_signed_context_required` enforces `app_security_context_valid()` on `users` and `auth_otps`. Unauthenticated users submitting credentials do not possess a session token or `userId`.

### 1.1 Support for Unauthenticated `'AUTH'` Security Realm
In `src/lib/services/securityContextService.ts`, line 118 currently validates:
```typescript

  throw new Error('SECURITY_CONTEXT_MISSING: Authenticated user context is required for this realm.');

```
**Required Update:** `securityContextService.ts` must be updated to exempt `realm === 'AUTH'` when `userId` is empty (`""`).

### 1.2 HMAC Signature Payload Compatibility
In `20261119000001_stage2_1_signed_security_context/migration.sql`, the payload calculation converts empty `userId` (`""`) to a length-prefixed string `'0:'`. The HMAC signature generated by `withSecurityContext({ realm: 'AUTH', userId: '' })` is mathematically valid and fully verified by `app_security_context_valid()` in PostgreSQL.

### 1.4 Protection Against Auth Abuse Vectors
- **User / OTP Enumeration Prevention:** Login handlers use timing-safe bcrypt comparisons against `DUMMY_HASH` (`auth.ts#L100`) for unknown emails, ensuring response times are indistinguishable.

## 2. Reusable API Security Wrapper (`withApiSecurityContext`)

All Next.js API route handlers under `src/app/api/` will be wrapped using `withApiSecurityContext` in `src/lib/authWrapper.ts`:

### 2.1 TypeScript Interface & Implementation Specification

```typescript
// Specification for src/lib/authWrapper.ts

import { NextRequest, NextResponse } from 'next/server';
import { getCurrentUser, AuthenticatedUser } from './auth';
import { withSecurityContext, SecurityContextInput } from './services/securityContextService';
import { Prisma } from '@prisma/client';

export interface ApiSecurityOptions {
  /** Security Realm (defaults to 'STAFF') */
  realm?: 'STAFF' | 'CUSTOMER' | 'WORKER' | 'PUBLIC_QR' | 'AUTH';
  /** Required resource permission e.g. 'inventory' */
  resource?: string;
  /** Required action permission e.g. 'read' */
  action?: string;
  /** Roles authorized to bypass permission check (e.g. ['Admin']) */
  roles?: string[];
  /** Allow unauthenticated access under 'AUTH' or 'PUBLIC_QR' realm */
  allowAnonymous?: boolean;
}

export type AuthenticatedApiHandler<T = any> = (
  req: NextRequest,
  context: {
    user: AuthenticatedUser | null;
    securityContext: SecurityContextInput;
    tx: Prisma.TransactionClient;
    params?: any;
  }
) => Promise<NextResponse | T>;

/**
 * Higher-order function wrapping API handlers with authentication,
 * RBAC permission verification, and transaction-bound signed security context setup.
 */
export function withApiSecurity<T = any>(
  options: ApiSecurityOptions,
  handler: AuthenticatedApiHandler<T>
) {
  return async (req: NextRequest, routeParams?: { params: Promise<any> }) => {
    try {
      const realm = options.realm ?? 'STAFF';
      let user: AuthenticatedUser | null = null;

      // 1. Authenticate Request for Authenticated Realms
      if (!options.allowAnonymous && realm !== 'AUTH' && realm !== 'PUBLIC_QR') {
        user = await getCurrentUser(req);
        if (!user || !user.isActive || user.deletedAt) {
          return NextResponse.json({ error: 'UNAUTHORIZED: Active session required.' }, { status: 401 });
        }

        // 2. Evaluate RBAC Permissions
        if (options.resource && options.action) {
          const hasPerm = user.role.permissions?.some(
            (rp) => rp.permission.resource === options.resource && rp.permission.action === options.action
          ) || user.role.name === 'Admin';

          if (!hasPerm) {
            return NextResponse.json(
              { error: `FORBIDDEN: Missing permission "${options.resource}:${options.action}".` },
              { status: 403 }
            );
          }
        }
      }

      // 3. Resolve Security Context Input
      const secContext: SecurityContextInput = {
        userId: user?.id ?? '',
        branchId: user?.branchId ?? '',
        branchPath: user?.branch?.path ?? null,
        departmentId: user?.departmentId ?? null,
        accessScope: user?.accessScope ?? 'Own',
        realm,
      };

      const resolvedParams = routeParams?.params ? await routeParams.params : undefined;

      // 4. Execute Handler inside Signed Security Context Transaction
      return await withSecurityContext(secContext, async (tx) => {
        return await handler(req, {
          user,
          securityContext: secContext,
          tx,
          params: resolvedParams,
        });
      });
    } catch (err: any) {
      console.error('[API Security Wrapper Error]:', err);
      return NextResponse.json({ error: err.message ?? 'Internal server error' }, { status: 500 });
    }
  };
}
```
